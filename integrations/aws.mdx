## Overview

Lawdie uses two AWS services under the hood:

| Service | Purpose |
|---------|---------|
| **AWS S3** | Stores uploaded documents, generated DOCX/PDF files, and call recordings |
| **AWS SES** | Delivers system emails (account notifications, document delivery) |

These are infrastructure components — most users don't need to configure them directly. This page is for self-hosted deployments or administrators setting up a new environment.

## S3 configuration

Documents uploaded in the chat and files generated by the Document Drafting agent are stored in an S3 bucket.

### Required IAM permissions

Your AWS IAM user or role needs the following permissions on the bucket:

```json
{
  "Effect": "Allow",
  "Action": [
    "s3:GetObject",
    "s3:PutObject",
    "s3:DeleteObject",
    "s3:ListBucket"
  ],
  "Resource": [
    "arn:aws:s3:::your-bucket-name",
    "arn:aws:s3:::your-bucket-name/*"
  ]
}
```

### Environment variables

```bash
REACT_APP_AWS_REGION=us-east-2
REACT_APP_AWS_ACCESS_KEY_ID=AKIA...
REACT_APP_AWS_SECRET_ACCESS_KEY=your-secret
REACT_APP_S3_BUCKET_NAME=lawdie-doc-storage
```

### Bucket configuration

- Enable **versioning** to protect against accidental overwrites
- Set a **lifecycle policy** to expire temporary upload files after 7 days
- Block all public access — Lawdie generates pre-signed URLs for file access

## SES configuration

SES is used for outbound system emails. To use SES in production:

1. Verify your sending domain in the AWS SES console
2. Move out of the SES sandbox (required to send to unverified recipients)
3. Set your verified sending address in the backend `.env`

## Troubleshooting

| Issue | Fix |
|-------|-----|
| Document upload fails | Check IAM permissions and bucket name in `.env` |
| Files not appearing after upload | Verify the S3 bucket region matches `AWS_REGION` |
| SES emails not delivered | Confirm domain verification and sandbox status in the AWS console |
